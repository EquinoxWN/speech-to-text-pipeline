## Measure: the two-utterance demo (`stt transcribe`)

`.tmp/demo_44k_stereo.wav`: 3 s silence, en_us_0001, 4 s silence, en_us_0000, 2 s silence, upsampled
to 44.1 kHz stereo (28.32 s). Output: language en (0.99); speech kept 14.03 s, removed 14.29 s; 1
chunk, 2 engine calls; segments at 3.416-8.936 s, 9.316-10.716 s and 17.752-24.572 s of the
original file. The second clip starts at 3 + 8.76 + 4 = 15.76 s of input and its first word at
about 16.6 s (0.87 s into the clip, as in the padded run), but VAD marked speech only from 17.752 s
in this file, so "However" was cut out before transcription.

## Analyze

- **Resampling** keeps pitch within 1 Hz (440 Hz from 44.1 kHz, 1 kHz from 8 kHz) and removes a
  12 kHz tone instead of folding it to 4 kHz (RMS < 0.01 against 0.35 for a naive decimation).
- **VAD** removed all added silence on the 8 clips and 4.97 to 10.04 s per clip in total; a steady
  1 kHz tone is not taken for speech.
- **Timestamps:** adding 5 s of silence in front shifts every word by 5.0 s within 0.05 s, and the
  same words come out, so the time map and the chunk offsets hold on real model output.
- **Defect found:** the first version lost the second utterance of the demo. Whisper ended the
  window after "sentence." because VAD had removed the pause between the utterances. Root cause and
  fix are in the [quality check](../quality/2026-11-01.md) and RFC 0001 ("Resume pass").
- **Error rates** are Whisper tiny's: high on id_id_0001 (0.556: "britania ... jerman" heard as
  "kita nihnya ... cerman") and on Chinese, where tiny writes Traditional characters against
  Simplified references (for example 這/这, 屬/属), which counts as errors. Eight clips cannot rank
  languages or models; that is M3.

## Improve

- Resume pass: the demo went from one transcribed sentence to both (1 to 2 engine calls). The first
  word of the second sentence ("However") is still missing: VAD did not include it in a speech span
  in this file (on the same clip padded with digital silence it does), which is not fixed in M1.
- Own decoder on PyAV's resampler instead of `faster_whisper.decode_audio` (which fails on PyAV 19),
  with the length cap enforced while decoding.
